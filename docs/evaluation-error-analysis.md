# Evaluation Results and Error Analysis

Everything here is regenerated by two commands and needs no Docker or database:

```bash
python evaluation/generate_corpus.py && python evaluation/run_eval.py --label after-fixes
python evaluation/generate_corpus.py --profile challenge && python evaluation/run_eval.py --corpus evaluation/corpus_challenge --label challenge-after-fixes
```

Definitions, ground-truth tiers and the targets (declared before measuring) are in [labels-and-thresholds.md](labels-and-thresholds.md).
Raw outputs (tables, `metrics.json`, per-error `errors.json`) are under `evaluation/results/`.

Targets: device P ≥ 0.90, R ≥ 0.90, FPR ≤ 0.05, high-priority recall ≥ 0.95, evidence completeness 100 %, p95 ≤ 250 ms.
After the fixes every target is met **except high-priority recall (0.906 on the standard corpus)**; see §3.1.

What the comparison shows (standard corpus, after fixes):

* A plain `diff -u` has perfect recall but flags 68 % of healthy devices (cosmetic noise, authorized changes, out-of-policy edits).
* Normalizing and tree-diffing the whole config (system B) removes cosmetic noise but still flags 36 % of healthy devices: it cannot tell policy-relevant from irrelevant changes, nor authorized from unauthorized ones.
* Ticket matching is the largest single contributor to precision (removing it: precision 0.79, FPR 0.28; authorization accuracy 0.75).
* ACL order analysis contributes recall (removing it misses 3 ACL changes: precision unchanged, recall 0.94).
* Semantic normalization contributes little *on this corpus* (precision 0.98 without it, 2 extra finding-level false positives): the parser already canonicalizes VLAN lists and token order, and the corpus has few comparison-layer-only variations. This is reported as measured, not as evidence that normalization is unnecessary.

## 2. Defects found by the harness, and what was done

Every false positive, false negative and false alarm in the first run was inspected (`errors.json`). They reduce to five root causes, all fixed and covered by regression tests in `backend/tests/unit/test_parser_hardening.py`.

| # | Symptom (before) | Evidence | Root cause | Fix |
|---|---|---|---|---|
| D1 | **Every Lab device raised a false High alert** | 34 false-positive findings; all 19 Lab devices alerted; 8 wrong tiers | The seed-style wildcard rule `interface.*.port_security.enabled` expanded over trunk uplinks and SVIs (`GigabitEthernet0/1`, `Vlan99`), which can never have port security | `resolve_wildcard_key_paths` now scopes `interface.*.port_security.*` to `switchport mode access` ports (`normalization.py`) |
| D2 | **Valid configs rejected as `PARSE_ERROR`** (critical alert on a healthy device) | 7 devices: `ntp server … prefer` ×3, `snmp-server location Block B, Floor 2` ×2, login banners ×2; challenge: non-ASCII text ×4 | The parser ran `canonicalize_ip` on the whole NTP argument and rejected any unrecognized global line containing punctuation or `^C` banner delimiters | NTP options/VRF/DNS names parsed; banner bodies skipped until the closing delimiter; unrecognized lines rejected only if they contain control/non-printable characters; an **unterminated** banner is a `ParseError` so it can never swallow the config silently |
| D3 | **Silent false negative: Telnet on `line vty 0 4` missed** | 3 devices; hard-compliance (critical) violation reported as `Compliant` / downgraded | VTY ranges were keyed by line type only, so `line vty 5 15` (SSH) overwrote `line vty 0 4` (Telnet) | `merge_transport_input`: the policy value is the union across ranges, and `none` never masks a protocol |
| D4 | Documentation changed an ACL verdict | challenge: 3 devices, false High alert | `remark` lines counted as ACL entries | remarks dropped from ACL trees |
| D5 | **No evidence citation** for high-priority outputs | 0 of 34 high-priority events complete (missing `source_line`) | Evidence bundles carried key path / expected / actual / rationale but not the config text | New `app/services/evidence.py`: each detail cites the offending running-config line and line number (or the container stanza / explicit `(absent)` note for missing items); `source_line` and `source_line_number` added to `DriftDetailOut` |

Order of events (for honesty about what is held out): D1-D3 and D5 were found on the standard corpus and fixed. The challenge corpus
(`generate_corpus.py --profile challenge`) was authored *afterwards* and run once with those fixes in place (`results/challenge-first-run`):
precision 0.75 / FPR 0.16, exposing D4 and the non-ASCII case of D2. Those two were then fixed; the challenge corpus is therefore **no longer held-out
for D2/D4**, and the standard corpus is **in-sample for D1-D3 and D5**. The `after-fixes` numbers are regression results, not generalization estimates.
The first-run challenge numbers are the honest generalization estimate for fresh constructs.

## 3. Errors that remain

### 3.1 Zone multipliers demote high-impact changes (calibration, 5 devices, standard corpus)

| Devices | Change (ground-truth tier) | Score | System label |
|---|---|---:|---|
| `sw-hst-03`, `sw-hst-04`, `sw-hst-09` | ACL order inversion, ACL entry removed, trunk leak (HIGH) | 85 × 0.8 = 68 | Drift-Unauthorized-**Medium** |
| `sw-evt-03`, `sw-evt-07` | access port on management VLAN, trunk leak (MEDIUM) | 85 × 0.5 = 42 | Drift-Unauthorized-**Low** |

Detection is correct in all five; only the *priority* is lower than the expert judgement. Consequence: high-priority recall 0.906 against a 0.95 target
(three segmentation breaches in student hostels fall under the score-80 alert threshold, so no `CRITICAL_DRIFT` alert fires for them).
This is a **policy calibration** question, not a code defect: the 0.8 hostel factor encodes "hostel ports matter less" while the judgement table says
segmentation breaches matter equally everywhere.

Options (none applied, because the judgement table is single-annotator and the tuning folds disagree, see §4):

1. Raise the severity weight of segmentation rules (trunk, ACL, access-VLAN) to 100 so hostels reach 80.
2. Lower the high-priority threshold: F1 over all devices peaks at 60 (1.000) vs 0.951 at 80; but the two tuning folds chose 60 and 80 respectively, so the data cannot settle it.
3. Make zone multipliers apply to *exposure* rules only. WP7 stakeholder sessions should confirm the judgement table before any change.

### 3.2 A single rule cannot grade *how bad* a VLAN change is (challenge corpus, 2 devices)

`c_access_vlan_other` (edge port moved to a non-management VLAN) is judged MEDIUM but scores 85 (High) because the same rule also guards against the
management-VLAN case. Detection is correct; the rule would need two thresholds (or a second rule for the management VLAN) to grade them separately.

### 3.3 Known limits, not measured as errors

* Only Cisco IOS syntax is parsed (WP3 adds FRR); the corpus therefore contains only IOS-style text.
* Rules cover five drift families; out-of-scope changes (descriptions, VLAN names, logging hosts, timeouts) are deliberately *not* drift. A reviewer who disagrees with that scope will count them as false negatives.
* `ntp server <dns-name>` is parsed as a name and compared as text, so a resolvable alias of the approved IP is reported as drift.

## 4. Held-out threshold tuning

Two folds (fit on one half, report on the other, then swap). Ticket grace: both folds choose the shipped **30 minutes**
(authorization accuracy 1.00 at 30 vs 0.97 at 0/15 and 0.94 at 60), which supports the default.
High-priority threshold: the folds disagree (60 vs 80), because the three hostel misses all fall in one half. Over all devices F1 is 1.000 at 60 and 0.951 at 80;
with 3 affected devices this is suggestive, not conclusive, so the shipped default is unchanged. See `results/after-fixes/results.md` §9.

## 5. Threats to validity

* **Synthetic and single-author.** Configurations, rules, tickets and ground truth were written by the same person who built the detector; the challenge corpus mitigates but does not remove this. WP7 adds external validation.
* **Ground-truth tiers are one person's judgement** (labels-and-thresholds.md §2); label accuracy depends on it.
* **In-sample after fixes** (see §2). Treat 100 % device-level numbers as regression guards.
* **Small n.** 96 devices counted, 49 positives: the 95 % interval on a perfect precision is [0.93, 1.00]. Intervals are in `results.md`.
* **Latency** is normalize + persist + drift + score on in-memory SQLite (p95 ≈ 8 ms, normalization alone ≈ 0.3 ms). It excludes SSH collection and Postgres round trips; WP5 measures scale.
* **Baseline definitions matter.** System A diffs against each device's own last-known-good; a global golden file would do worse.

## 6. Where the checks live

* `backend/tests/unit/test_evaluation_harness.py`: corpus determinism, ground-truth invariants, metric helpers, and **regression gates** (device P/R ≥ 0.90, FPR ≤ 0.05, evidence 100 %, p95 < 250 ms, authorization 100 %, unterminated banner → `PARSE_ERROR`).
* `backend/tests/unit/test_parser_hardening.py`: one test group per defect D1-D5.
